# QuarkZip translations (i18n)

QuarkZip's UI is fully translatable at runtime — no restart, no rebuild per
language. The model is borrowed from [XDM](https://github.com/subhra74/xdm)
(`app/XDM/Lang/<Language>.txt` + `index.txt`): **one file per language** plus
**one registry entry**, so a translation contribution is a two-file PR.

## Shipped languages

| Code | Language | File |
| ---- | -------- | ---- |
| `en` | English (default, canonical) | `src/i18n/locales/en.json` |
| `hi` | Hindi (हिन्दी) | `src/i18n/locales/hi.json` |

## How the code works

* `src/i18n/locales/en.json` — canonical key set (100 keys). **Never rename
  keys here without updating every other locale** — `npm run i18n:check`
  enforces parity.
* `src/i18n/locales/<code>.json` — translated values, same keys.
* `src/i18n/locales.ts` — registry (`LOCALES`: code, English label, native
  label, text direction). The XDM `index.txt` equivalent.
* `src/i18n/LanguageContext.tsx` — `LanguageProvider` + `useLanguage()`
  returning `{ lang, setLang, t }`. Detection: saved choice
  (`quarkzip.lang`) → `navigator.language` → English. Region fallback is
  automatic: `pt-BR` → `pt` → `en`, and every key falls back to English
  individually, so partial translations never blank the UI.
* `src/LanguageSwitch.tsx` — footer language menu (same shell pattern as the
  page-size menu). Counts, grouped numbers and dates follow the active
  language via `formatCount` / `formatDateTimeLocal` (`src/format.ts`).
* `t(key, vars)` interpolates `{placeholders}`: `t("extract.allFiles",
  { total: 6 })`. Brand names (`QuarkZip`, `7zz`, `7-Zip`) stay untranslated.

## Contribute a translation (PR in ~10 minutes)

1. Copy the canonical file:
   ```sh
   cp src/i18n/locales/en.json src/i18n/locales/<code>.json
   ```
   Name it BCP-47-ish: `fr.json`, `pt-BR.json`, `zh-Hant-TW.json`.
2. Translate **values only** — never the keys. Keep every `{placeholder}`
   exactly as-is (you may reorder them to fit your grammar).
3. Register it in `src/i18n/locales.ts`:
   ```ts
   { code: "<code>", label: "<English name>", native: "<native name>", dir: "ltr", strings: <code> },
   ```
   plus the `import <code> from "./locales/<code>.json"` line. Use
   `dir: "rtl"` for Arabic/Hebrew/Persian/Urdu (the app sets
   `document.dir`; layout is symmetric so RTL is best-effort).
4. Verify locally:
   ```sh
   npm run i18n:check   # key parity + placeholder parity + registry
   npm test              # parity is also asserted in src/i18n/i18n.test.tsx
   ```
   Then open the app, pick your language in the footer menu, and eyeball
   the empty state, an open archive, the extract dialogs, and About.
5. Open the PR with title `feat(i18n): add <Language> (<code>)`.

Region variants (`pt-BR` vs `pt-PT`) are welcome as separate files — the
fallback chain picks the closest match for each user automatically.

## Notes for translators

* Formality: match what mainstream desktop apps use in your language.
* `…` (ellipsis) and `·` separators: keep them; they are layout rhythm.
* Long strings (the About license paragraph) wrap — keep them concise.
* Never translate: `QuarkZip`, `7zz`, `7-Zip`, `7-zip.org`, file extensions
  (`PNG`, `7Z`), format names, or `{placeholders}`.
